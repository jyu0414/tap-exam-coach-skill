# お試しテスト（いつでも・サクッと合格の見込みを確かめる）

「今受けたら受かりそう？」「ちょっと実力を見たい」に応えるモード。計画の週に関係なく、いつでも始められる。初期設定の前（記録がない状態）でも、試験名さえ分かれば始められる。

模試モード（`mock-mode.md`）との違い:

| | お試しテスト | 模試 |
|---|---|---|
| 目的 | 今の見込みをざっくり知る | 本番と同じ条件で測る |
| 問題数 | 既定20問（10/20/30から選べる） | 本番どおり、または縮小版 |
| 時間 | 計らない（希望すれば按分して計る） | 本番の制限時間 |
| 計画との関係 | なし。判断点にも使わない | 計画の週に置く。判断点になる |
| 所要 | 15〜30分 | 1〜3時間 |

## 1. 始める前

記録（`progress.md`）があれば `exam-profile.md` を使う。なければ、試験名だけを確かめて（版が複数あるときは版も）、出題範囲・比率・出題形式・合格基準の4つを調べる（`setup.md` 2章のうち、この4つだけでよい）。調べる範囲は絞るが、調べ方は手を抜かない。**実施団体の公式資料（試験ガイド・試験要綱）を実際に開いて**数字を取る。検索結果の要約や記憶、他の数字からの逆算（「3分野が30/26/24だから残りは20」）で埋めない。お試しテストの配分と合否の目安はこの4つで決まるので、ここが違うと結果の意味がなくなる。公式資料で確かめられなかった項目は「未確認」とし、そのぶん結果の確からしさが下がることを伝える。調べた結果は `exam-profile.md` に出典つきで残す（後で初期設定に進むときに使える）。

開始前に示すこと（1メッセージで短く）:
- 問題数（既定20問。変えたければ選んでもらう）と、分野ごとの配分
- 途中で正誤も解説も出さないこと、最後にまとめて採点すること
- 学習がまだの分野からも出ること（今の実力を測るため）

「始めて」と言われたら、すぐ1問目に入る。開始前に質問を重ねない（サクッとが目的なので）。

## 2. 問題の組み方

- 分野配分は公式の出題比率で按分し、**全分野から最低1問**。20問なら比率の大きい分野が3〜4問になる
- 難易度は本番と同じ。易しい問題で埋めると見込みが甘くなり、利用者の判断を誤らせる
- 出題形式は本番どおり（`formats.md`）。短答や大問がある試験では、20問の枠の中に本番と同じくらいの割合で入れる。大問は時間がかかるので、お試しテストでは設問を2〜3個に絞った短い大問にしてよい
- 学習モードや過去のお試しテスト・模試で出した問題は使わない
- 全問の正解・分野・小項目・論点を、出題前に `quick-check-YYYYMMDD.md` に書いておく（中断しても採点できるように）
- 正解位置の分散、見出しは番号だけ（「お試し 問5/20」）、おすすめ印のルールは学習モードと同じ

## 3. 進め方

- 1問ずつ出し、回答は「記録しました」とだけ返して次へ。正誤が分かる言葉は出さない
- 択一だけなら、利用者が望めば AskUserQuestion で4問ずつまとめて出してよい
- 回答は出題ごとに記録ファイルへ追記する

## 4. 結果

最後にまとめて出し、`mock-results.md` に「お試し」として追記する。

1. **総合**: 正答数と正答率
2. **見込み**: 「合格圏 / ボーダー / 要補強」の3段階（区分は `mock-mode.md` 4章と同じ）
3. **確からしさ**: 20問程度では1問で5ポイント動くので、ぶれが大きいことを数字で書く（例: 「20問中14問（70%）。1〜2問の差でボーダーと合格圏が入れ替わる幅です」）。スケールスコア・CATの試験では正答率と合否が一対一でないことも書く
4. **分野別**: 分野ごとの正答（問題数が少ないので「○問中○問」で示し、%だけで判断させない）。比率の大きい分野で落としているかを一言
5. **次の一手**: 1〜3行。例: 「D1とD2の誤答が多いので、今週の学習をD1から始めるのが効きそう」「全体に合格圏。模試で時間配分を確かめる段階」
6. **誤答の解説**: 「誤答だけ解説しますか」と聞き、希望すれば学習モードの解説の型で解説し、弱点ノートに書く

記録がまだない利用者には、最後に「この結果をもとに受験日までの計画を作りますか」と一言だけ添える（作るなら `setup.md` へ。お試しの結果は不得意分野の初期値に使える）。

計画がある利用者でも、お試しテストの結果で計画や受験日を変えない。見直しが要りそうなら、そう伝えるだけにする。
