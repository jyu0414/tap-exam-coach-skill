# 出題ルールと回答UI（学習モード）

出題する前に毎回読む。ここに書いたルールの多くは、実際の学習で利用者が困ったことから決めたもの。理由を理解したうえで守る。

## 1. 1問の流れ

1. 進行表（`weak-notes-wN.md`）に、これから出す問題の番号・小項目・論点・**正解**を先に書く。正解位置の分布を管理するため
2. 問題を出す（見出し、問題文、本番と同じ数の選択肢。図が要れば図）
3. 回答を受け取る（択一はタップ、短答は入力）。回答前に正解やヒントは一切出さない
4. 正誤を示し、解説する（6章）
5. 進行表に回答と正誤を書き、誤答なら弱点ノートにも書く（`references/review.md`）
6. 次の問題へ

利用者が回答せずに質問してきた（「〇〇ってどういう意味？」）ときは、正解が分かってしまわない範囲で答えるか、「回答後に解説します」と伝える。

## 2. 回答UI

利用者はスマホでも使うので、記号を打つより選択肢をタップしたい。ここは択一（選択肢4つ以下）の場合。5択以上・複数選択・短答・図表つきは `formats.md` を見る。記号は本番どおり（IPAならア〜エ）。以下の例は A〜D で書く。

### Claude Code（AskUserQuestion がある場合）

- 1問につき1回 AskUserQuestion を呼ぶ
- `header`: 「問3/25」（番号だけ。12文字以内）
- `question`: 問題文そのもの。ダイアログだけが表示されて直前のメッセージが見えないことがあるので、問題文は question に全文入れる
- `options`: 本番の選択肢の数（2〜4）。`label` は本番の記号（「A」〜「D」、「ア」〜「エ」など）、`description` に選択肢の本文（日英併記なら英語も）
- `multiSelect`: false（「2つ選べ」の問題だけ true）
- **label に「(Recommended)」を付けない。** AskUserQuestion はおすすめ印なしで出せるので、3章の問題は起きない
- 「Other」は自動で付く。利用者がOtherで「わからない」「Bかな…」などと書いたら、書かれた内容で回答として扱う（記号が読み取れなければ確認する）

例:

```
header: "問3/25"
question: "ある組織が保存データと転送中データの両方を保護したい。最も適切な組み合わせはどれか。"
options:
  - label: "A", description: "保存中はAES、転送中はTLS"
  - label: "B", description: "保存中はRSA、転送中はIPsec"
  - label: "C", description: "保存中はSHA-256、転送中はTLS"
  - label: "D", description: "保存中は3DES、転送中はSSH"
```

### Claude.ai の新しいプロジェクト（メイン画面＋スレッド）

`post_widget` や `ask_decision` / `request_decision` というツールがあり、ライブラリのファイルが `/mnt/project-files/` に見えるなら、この環境。2026-11-14 に Web とスマホアプリで確かめた内容:

| ツール | Web（PC） | スマホアプリ | 選択肢 | おすすめ印 | 注意 |
|---|---|---|---|---|---|
| `post_widget`（widget: `card`）※使わない | ボタンつきで表示され、押すと回答が届く | **カードが表示されず、プレビュー用の1文だけが出る**（新しく出した問題でも同じ） | ボタン4つまで | なし | ボタンが2つ以上だと一度断られるので最初から `card_as_is: true`。ラベル30字、本文の段落1000字、ブロック12個まで |
| `ask_decision`（メイン）/ `request_decision`（スレッド） | 表示される | **表示され、タップで答えられる**（CISSP・CCDV学習で利用者がスマホから回答） | 2〜4個 | **必ず1つに付く** | ラベル40バイト、各選択肢の説明（必須）200バイト、質問は300バイトの1文でMarkdownなし |

**出題も確認も、すべて決定カードに統一する。** 同じスレッドをスマホとPCの両方で開くことがあり、`post_widget` で出した問題はスマホでは見えなくなるため。`post_widget` は使わない（「次の週へ」のような確認も決定カードで出す）。

決定カードでの出題:

- 問題文と選択肢の全文（「A 保存中はAES、転送中はTLS」）は、カードの直前の通常メッセージに書く（カードの質問欄は300バイトしか入らない）
- カードの質問欄は「問3/25 上の問題の答えはどれか（おすすめ表示は正解と関係ありません）」
- 選択肢のラベルは本番の記号（「A」〜「D」）、説明欄には選択肢の本文を短く入れる（200バイトに収まらなければ「上のAの選択肢」）
- おすすめ印は3章のルールで**常に先頭（A）に固定**する。正解位置はA〜Dに均等に散らし、Aが正解の問題も必ず混ぜる。CCDV学習ではこの印に引かれてAを選んだ誤答が出ているので、週末に「Aへの誤答」が多くないかを数える
- 問題の要約や見出しに答えの手がかりを書かない（実例: 「長期認証情報なしでアクセスする方法を選ぶ問題」と書かれ、答えのIAMロールが透けた）
- 選択肢が5つ以上、または「2つ選べ」で組合せが5通り以上になるときは、文字で答えてもらう

### Claude.ai のふつうのチャット

タップすると回答が届く質問カードのツール（名前は環境で違う）があれば、それを使う。問題文は直前の通常メッセージに全文書き、カードの質問欄には「問3/25 上の問題の答えは？」、選択肢には本番の記号と本文を入れる。おすすめ印は付けない。2026-11-14 に Web で、カードが出てタップで回答が届くことを確かめた。

### 共通の注意

- 会話の最初に使えるツールを確かめ、決めたらその会話ではずっと同じ方法を使う（ある回だけ文章で聞く、を混ぜない）
- 選択肢を並べて表示するだけのカード（押しても何も送られないもの）は使わない
- 利用者が「カードが出ない」と言ったら、謝って文章に切り替えるのではなく、上の表の次の候補で出し直す。どれも出せないときだけ文章にして「A〜Dの1文字で答えてください」と頼む
- タップのカードがまったく使えない環境では、通常メッセージで出し、最初に1回だけ「この環境では選択肢カードが使えないため、文字で答えてください」と理由を伝える

## 3. 「おすすめ」印の扱い

UIがどれか1つに「おすすめ」印を付けないと出せない場合だけ、このルールを使う（Claude Code の AskUserQuestion は不要）。

CISSP学習で起きたこと:
- 印を常にAに付けていたら、Aへの誤答が多かった。第2週は誤答8問中5問がAで、30秒以内の速い回答に多かった
- 対策として「Aを選ぶ理由を確かめて」と書いたら、直後にAを避けて誤答した（正解はAだった）

ルール:
1. おすすめ印は**常に先頭の選択肢（A・アなど）に固定**し、毎回「おすすめ表示は正解と関係ありません」と書き添える
2. 正解位置は全選択肢に均等に散らす。**先頭が正解の問題も必ず混ぜる**（Aを避ければ当たる、を作らない）
3. 正解位置に関わる声かけはしない（「Aに注意」「Aを避けて」などは書かない）
4. 回答までの時間が分かるなら記録し、速い誤答がAに偏っていないかを週末に見る

印が不要な環境でも、2と3は守る（正解位置の偏りは、印がなくても回答の癖を生む）。

### 正解位置の分散

- 4択25問なら A6/B6/C7/D6 程度（5択なら各5問）。週の最初に目標分布を決め、進行表で残りを数えながら配る
- 連続して同じ位置が3問以上続かないようにする
- 同じ論点の選択肢を作るとき、正解を「一番もっともらしい位置」に置きがちになるので、先に位置を決めてから選択肢を並べる

### 回答時間（分かれば）

Claude Code なら Bash の `date +%s` を出題直前と回答受信直後に取れば秒数が分かる。取れない環境なら記録しない（推測で書かない）。

## 4. 問題文のルール（公式問題集に合わせる）

1. **見出しは番号だけ**（「問3/25」）。小項目名や分野名は出さない（ヒントになるため）。週の中でも小項目の順番はシャッフルする
2. **日英併記**は試験の受験言語に合わせる。CISSPの日本語受験では、日本語の問題文・選択肢の下に英語原文を付けた（公式問題集の形式）。日本語だけの試験（支援士など）なら不要。英語受験なら英語だけでよいか、日本語訳を付けるか利用者に合わせる
3. **略語は公式問題集の書き方**にそろえる。選択肢が用語そのものなら「個人識別情報（PII）」の形。問題文中の略語は DLP、TLS、AES のようにそのまま。独自に「AES（Advanced Encryption Standard）」のような正式名称の補足は付けない
4. **選択肢の形をそろえる**。すべて同じ分野の実在する用語や施策で、同じ形・長さ・具体性にする（例: 「保存中はAES、転送中はTLS」型を4つ）。明らかに誤りの選択肢や、正解だけ長い・正解だけ具体的な選択肢、理由を書き添えた選択肢（「〜のため」。理由の当否で絞れてしまう）は作らない。本番の選択肢が理由つきの形式のときだけ例外
5. **問い方を混ぜる**。短い知識問題と、シナリオ問題（「最も適切な」「最初に行うべき」）を混ぜ、シナリオは**約4割**
6. **本番より簡単にしない**。難易度は公式問題集・公開過去問を基準にする。図が要る論点は図を省かない（`formats.md` 6章）

日英併記の例:

```
問7/25
情報システムのデータオーナーの責任として最も適切なものはどれか。
Which of the following is the MOST appropriate responsibility of a data owner?

A データの分類レベルを決定する / Determining the classification level of the data
B データのバックアップを実施する / Performing backups of the data
…
```

## 5. 出題前の点検

問題を出す前に、頭の中で次を確かめる。1つでも引っかかれば作り直す。

- [ ] 正解が1つに決まるか（別の選択肢も条件次第で正解にならないか）
- [ ] 本番と同じ形式（記号・選択肢の数・複数選択・短答・図）か
- [ ] 選択肢の形・長さ・具体性がそろっているか
- [ ] 図表を使った問題なら、図が問題文の条件どおりで、図にヒントがないか
- [ ] 短答なら、模範解答と採点基準（必須要素・別解）を進行表に書いたか
- [ ] すべての選択肢が実在する用語・施策か（でたらめな用語で消去法が効かないか）
- [ ] 問題文に正解を示す言葉が含まれていないか（選択肢と同じ単語が問題文にある、など）
- [ ] 見出しに小項目名が入っていないか
- [ ] 進行表に書いた正解位置と一致しているか
- [ ] 本番の難易度より簡単になっていないか
- [ ] 学習モードで既に出した問題とほぼ同じになっていないか

## 6. 解説の中身

回答後に次を出す。

1. 正誤と正解（「不正解。正解は B です」）
2. 正解の理由
3. 他の選択肢がなぜ劣るか（それぞれ1〜2文）
4. 試験が求める判断軸（CISSPなら「マネージャー視点: 技術作業より先に方針・資産・リスクを考える」）
5. 似た用語の区別や覚え方（例: RMF「分類して選んで入れて確かめて許可して見張る」）。誤答したときは、**誤答した選択肢と正解の両方の定義を並べる**
6. 根拠は教科書・公式問題集を正とし、教材間で定義が揺れる論点は「教科書で要確認」と書く

利用者の職務経験が分かっていれば、「〇〇の現場経験があると△△を選びがちですが、試験では…」と触れてよい。

解説の最後に、次の問題へ進むことを短く伝え、そのまま次の問題を出す（毎回「次に進みますか」と聞かない。利用者が止めたいときは止めると言う）。

## 7. 週の流れ

1. 週の最初: `coverage.md` の割り当てを示す（小項目ごとの問題数、正解位置の目標、シナリオ数、想起テストの論点）
2. 本編を出題する（小項目の順はシャッフル）
3. 本編の後に想起テスト（`references/review.md`）
4. 週末: 結果をまとめ、`coverage.md` で抜けを照合し、`progress.md` を更新する
