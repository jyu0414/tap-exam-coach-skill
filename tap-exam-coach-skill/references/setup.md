# 初期設定: 入力・試験情報の調査・学習計画・割り当て

初回（`progress.md` がないとき）に行う。終わったら、利用者は「今週どの小項目を何問やるか」が分かり、すぐ1問目に入れる状態になる。

## 目次
1. 入力の受け取り
2. 試験情報の調査 → `exam-profile.md`
3. 週割の作成 → `plan.md`
4. 判断点
5. TODO
6. 小項目の割り当て → `coverage.md`

---

## 1. 入力の受け取り

### 必須

| 項目 | 例 | 備考 |
|---|---|---|
| 試験名 | CISSP、情報処理安全確保支援士、AWS SAA | 版（2024年版など）が複数あれば、どれかを確認する |
| 受験日 | 2027-01-31 | 未定なら「目標月」でよい。後で確定させる |

どちらかが欠けていれば、それだけを聞く。

### 任意（聞くのは1回だけ。答えがなければ既定値で進める）

| 項目 | 既定値 | 使い道 |
|---|---|---|
| 週あたりの学習時間 | 6〜10時間 | 週の問題数 |
| 開始日 | 今日の次の月曜 | 週割の起点 |
| 試験言語 | 試験の受験言語に合わせる | 日英併記の要否 |
| 得意・不得意な分野 | なし | 週割の配分、誤答分類の「〇〇視点」 |
| 職務経験 | なし | 解説で「あなたの経験だとこう選びがち」と触れる |
| 使う教材 | なし | 解説の根拠（教科書・公式問題集を優先） |

任意項目は1回で聞く。聞き方は次のとおり。

- **選択肢にできる項目はタップの質問UIで聞く**（学習時間「〜5時間／6〜10時間／11時間〜」、開始日「次の月曜／今日から」、試験言語「日本語／英語／日英併記」、受験時期など）。1回の呼び出しに複数の質問を並べられるUIなら（AskUserQuestion は4問まで）、まとめて1回で出す
- 各質問の選択肢に「おまかせ（既定値）」を入れるか、既定値の選択肢の説明に「既定」と書く
- 苦手分野・職務経験・教材のような自由記述は、質問UIの「その他」欄か、カードのあとに「あれば一言で（なければ不要）」と1行添えるだけにする
- 質問を番号つきの文章で並べて答えさせる形にはしない。質問UIがない環境に限り文章で聞く

**Claude.ai の新しいプロジェクト（決定カード）では、1枚ずつ順に聞く。** 2026-11-14 の CCAR-F 学習で、受験日を文章で、学習時間と言語を決定カード2枚で同時に聞いたところ、メイン画面には学習時間のカードしか出ず、利用者がそれに答えたところで止まったように見えた（残りの質問はスレッドの中にあり、気づかれなかった）。だから:

- 決定カードは**一度に1枚だけ**出す。答えが届いたら、同じ返信の中ですぐ次のカードを出す。聞く順は「受験時期 → 週の学習時間 → 問題文の言語」。それ以外の任意項目は聞かずに既定値で進め、計画の最後に「得意・苦手な分野や教材があれば一言で」と1行添える
- 受験日もカードで聞く。選択肢は今日から近い順に月で3つと「未定・ほかの日」（例: 「12月中／1月中／2月中／未定・ほかの日」）。「未定・ほかの日」なら文章で日付を聞く
- 利用者の答えを待つときは、必ずカードを出した状態で返信を終える。「〜が決まったら計画を作ります」のような文章だけで終えない（メイン画面に何も出ず、止まったように見える）
- 最後の答えが届いたら、確認を挟まずにそのまま計画づくりに進む

利用者が「任せる」と言うか答えなければ既定値で進め、何を既定値にしたかを `exam-profile.md` に書く。

週あたりの問題数の目安: 6〜10時間なら本編25問＋想起テスト数問。時間が少なければ15問程度、多ければ35問程度に増減する。

## 2. 試験情報の調査（Web検索）

調べて `exam-profile.md`（雛形: `templates/exam-profile.md`）にまとめる。**分からない項目は「未確認」と書き、推測で埋めない。** 間違った出題比率や形式で計画を作ると、計画全体が狂うため。

調べる項目:

- 公式アウトライン: 分野（ドメイン）と小項目、各分野の出題比率
- 本番の形式: 問題数、時間、出題方式（固定/CAT）、見直しの可否、合格基準
- 改訂予定: 受験日までに範囲が変わるか（例: CISSPは2027-04-15に新アウトライン。1月受験には影響なし）
- 受験言語と問題文の表記（日英併記の有無）
- 公式問題集の略語・用語の書き方（分かれば）
- **出題形式と開示の範囲**（次の節。出題の見た目を本番に合わせるために必須）

### 出題形式と開示の範囲を調べる

問題の「見た目」が本番と違うと、本番で戸惑い、練習の効果も落ちる。4択・A〜Dと決めつけず、科目ごとに次を調べて `exam-profile.md` の「出題形式」に書く。

**調べ方**: 実施団体の公式サンプル問題・公開過去問・受験案内（試験画面の説明、チュートリアル動画の説明文など）を見る。公開過去問があれば**実物を1〜2問必ず開いて読み**、問題文の書き方・選択肢の並べ方・図の入れ方・設問の問い方（「〇字以内」「字句を答えよ」など）を確かめる。要綱の説明だけでは見た目が分からず、作る問題が本番からずれるため。読んだ問題のURL（年度・問番号）を `exam-profile.md` に書く。見つからなければ公式問題集の記述や受験者向けの公式FAQ。非公式の受験記は補助としてだけ使い、出典を書く。

**科目ごとに調べる項目**:

| 項目 | 例 |
|---|---|
| 解答形式 | 択一（選択肢の数）/ 複数選択（「2つ選べ」）/ 組合せ（a〜cの正誤の組合せ）/ 短答（語句・数値・○字以内）/ 記述・論述（長文）/ 実技 |
| 選択肢の記号 | A〜D、ア〜エ（IPA）、1〜4、①〜⑤ |
| 選択肢の数 | 4つ、5つ（医師国家試験など）、AWSは4〜5個から1〜2個 |
| 図表 | ネットワーク構成図、E-R図、シーケンス図、表、グラフ、プログラムの擬似言語などが出るか、どの科目に多いか |
| 計算 | 計算問題の有無、電卓の可否 |
| 問題文の構成 | 短文単独 / 長文シナリオに設問が複数ぶら下がる（大問・小問）/ 空欄補充 |
| 試験中に画面で開示されること | 残り時間、問題番号と総数、分野名（CISSPは出ない）、見直しフラグの有無 |
| 結果で開示されること | 合否のみ / 総合点 / 分野別の評価（CISSPは不合格時のみ分野別の習熟度）/ 正解は非公開か |

**この調査から決めること**（`question-rules.md` に書き写す）:
- このスキルで扱う形式と扱わない形式。扱うのは 択一・複数選択・組合せ・短答（字数制限つきの短い記述を含む）・図表つきの問題。扱わないのは数百字以上の論述（論文試験など）と実技。扱わない科目がある試験では、初期設定の返答ではっきり伝え、`plan.md` の TODO に「△△は過去問・別教材で対策する」と入れる。黙って一部だけの計画を出すと、利用者は全科目を対策できていると思い込むため
- 選択肢の記号と数、図の出し方、模試・お試しテストで画面に出す情報と結果で出す情報（本番と同じにする）
- 形式ごとの細かいルールは `references/formats.md`

情報源は試験の実施団体の公式ページを最優先する。比率や問題数が非公式サイトでしか見つからなければ、その旨と出典を書く。

### 「未確認」が残ったとき

利用者に具体的に頼む。例:
- 「公式アウトラインのPDF（〇〇のページにあります）を共有してもらえれば、小項目を正確に取り込めます」
- 「合格基準が公表されていないようです。公式問題集に記載があれば教えてください」

小項目が未確認のままでも、分野レベルで計画は作れる。その場合は計画に「小項目は公式アウトライン入手後に確定」と書き、割り当ては分野単位で仮置きする。

CISSPでの記入例:

```
分野比率: D1 16 / D2 10 / D3 13 / D4 13 / D5 13 / D6 12 / D7 13 / D8 10 (%)
形式: CAT、100〜150問、最大3時間、前の問題に戻れない（2024年4月から日本語もCAT）
合格基準: 1000点中700点
```

## 3. 週割の作成

`plan.md`（雛形: `templates/plan.md`）に書く。

1. 開始日から受験日までの週数 N を数える
2. 最後の約4割を「模試と弱点補強」に充てる。残りを分野学習に配る
3. 分野学習の週は、分野の出題比率と**小項目数**で配分する。不得意分野は少し厚くする
4. 分野学習が終わる週に「模試1（判断点）」を置く
5. 以降は 弱点補強 → 模試2 → 模試3 → 総復習・受験 の順

週数が少ない（6週未満など）ときは、模試を1〜2回に減らし、分野学習も2分野を1週にまとめる。そのときは「この期間だと1分野あたりの演習が薄くなる」と率直に伝える。

CISSPでの実例（13週、週6〜10時間、約100時間）:

| 週 | 内容 |
|---|---|
| W1 | D1前半 |
| W2 | D1後半（リスク、BCP） |
| W3 | D2 |
| W4 | D3前半 |
| W5 | D3後半（暗号、物理） |
| W6 | D4前半 |
| W7 | D4後半＋D5前半 |
| W8 | D5後半＋D6 |
| W9 | D7＋D8＋模試1（判断点） |
| W10 | 弱点補強 |
| W11 | 模試2 |
| W12 | 模試3 |
| W13 | 総復習・受験 |

運用中に「D7が15項目と最多なのでD8を第10週前半へ移す」という調整が入った。計画は小項目数を見て組み、途中で動かせる前提にする。動かしたら `plan.md` の変更履歴に、日付・内容・理由を残す。

## 4. 判断点（受験日の見直し）

- 中間の模試（分野学習が一巡した直後）に判断点を置く
- 基準は合格基準より少し上にする。CISSPでは「正答率70%台前半未満なら受験を2〜4週後ろ倒し」
- 基準未満なら、後ろ倒し案（何週延ばすか、どの分野を補強するか、再予約の手間）を示して**利用者に決めてもらう**。スキルが勝手に計画を変えない
- 基準以上なら計画どおり進め、弱い分野を弱点補強週に回す

基準は `plan.md` に最初から書いておく。後から結果を見て基準を動かすと、判断点の意味がなくなるため。

## 5. TODO

計画とあわせて、受験準備で本人がやることを一覧にして `plan.md` に書く。CISSPの例:

- 公式アウトラインPDFの入手
- 最新版対応の教科書・公式問題集の選定
- 試験の予約（会場の空き状況も確認）
- 受験資格・実務経験要件の確認

試験ごとに必要なもの（申込期間、受験票、本人確認書類など）を調査結果から足す。

## 6. 小項目の割り当て（網羅性）

### なぜ先に決めるのか

CISSPの第1〜3週は「週25問を頻出論点から選ぶ」方式だった。第3週の終わりに利用者から「全部網羅できているか」と聞かれ、75問をアウトラインと照合したところ、D1の「1.8 人的セキュリティ」が0問だった。追加で19問を出して埋めた。割り当てを先に決めないと網羅は崩れる。

### ルール

- 週の最初に「小項目ごとの問題数」の割り当てを示してから出題を始める
- その週の範囲の**すべての小項目に最低1問**を割り当てる
- 残りの問題数は、出題比率・小項目の広さ・弱点で配る
- 正解位置の目標分布（本番の記号で）と、シナリオ問題の目標数（約4割）も一緒に示す
- 週末に、出した問題と小項目を照合し、抜けがあれば次週か弱点補強週に回す
- 割り当てと照合結果は `coverage.md`（雛形: `templates/coverage.md`）に記録する

割り当ての提示例（CISSP第5週、D3後半）:

```
3.6 暗号ソリューション 10 / 3.7 暗号解読攻撃 6 / 3.8 サイト・施設設計 3 / 3.9 サイト・施設の統制 6
= 本編25問 ＋ 想起テスト2問（Biba規則名、CCのPP/ST）
正解位置の目標: A6 / B6 / C7 / D6、シナリオ約10問
```

この割り当ては利用者に見せてよい（小項目は週の範囲として既に分かっている）。ただし個々の問題の見出しに小項目名は出さず、出題順はシャッフルする。

## 初期設定の締め

1. `exam-profile.md` `plan.md` `coverage.md` `progress.md` を保存する（`question-rules.md` も templates の内容を元に作る。利用者の指摘でルールが変わったらここに追記する）
2. 利用者に、計画の要約（週割の表、判断点、TODO、未確認事項）と第1週の割り当てを示す
3. 「第1週を始めますか」と聞き、始めるなら `references/question-rules.md` を読んで1問目へ
