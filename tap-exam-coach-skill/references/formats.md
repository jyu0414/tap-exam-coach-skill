# 形式別の出し方（択一・複数選択・組合せ・短答・図表）

`question-rules.md` の共通ルール（回答前に正解を出さない、見出しは番号だけ、正解位置の分散、出題前の点検）はすべての形式に効く。ここには形式ごとに違うところだけを書く。どの形式で出すかは `exam-profile.md` の「出題形式」に従い、本番にない形式は作らない（本番が4択なのに短答で練習しても本番の感覚に近づかないため）。`exam-profile.md` がないまま「〇〇形式で1問出して」と頼まれたときも、その科目の形式（科目名、設問の問い方、字数の目安）は公式資料か公開過去問を開いて確かめてから作る。

## 目次
1. 記号と選択肢の数を本番に合わせる
2. 択一（N択）
3. 複数選択
4. 組合せ問題
5. 短答（語句・数値・字数制限の記述）
6. 図表が要る問題
7. 大問・小問の構成

---

## 1. 記号と選択肢の数を本番に合わせる

- 記号は本番どおり: IPA試験なら ア〜エ、CISSPなら A〜D、数字の試験なら 1〜4
- 選択肢の数も本番どおり。5択の試験に4択で練習すると、消去法の感覚がずれる
- 正解位置の分散は選択肢の数で割る（5択25問なら各5問程度）

## 2. 択一（N択）

### 4つ以下（AskUserQuestion に収まる）
- `options` の `label` に記号（「ア」「イ」…）、`description` に本文
- `multiSelect: false`

### 5つ以上
AskUserQuestion は選択肢が2〜4個までなので、1つのダイアログに全部は入らない。次のどちらかにする。
- **問題文と選択肢をメッセージに書き、回答はテキスト入力**（「1〜5で答えてください」）。最も確実
- 4つ以下に分けてタップさせる方式は使わない（どちらのグループに正解があるかがヒントになるため）

## 3. 複数選択（「2つ選べ」）

- 問題文に「2つ選べ」のように選ぶ数を必ず書く（本番と同じ）
- 選択肢が4つ以下なら AskUserQuestion の `multiSelect: true`。5つ以上ならテキスト入力（「2つをカンマ区切りで」）
- 採点は全部合って正解（部分点なし）が多い。本番の採点方式を `exam-profile.md` で確かめ、それに合わせる
- 解説では、選ぶべき選択肢それぞれの理由と、選ばない選択肢それぞれの理由を出す

## 4. 組合せ問題（a〜cの正誤の組合せなど）

- 記述 a・b・c を問題文に並べ、選択肢は「a:正 b:誤 c:正」のような組合せにする
- 組合せの選択肢は、どの記述の正誤を知っていれば絞れるかが偏らないように作る（1つの記述だけで正解が決まると練習にならない）
- 解説では記述ごとに正誤の理由を出す

## 5. 短答（語句・数値・字数制限の記述）

情報処理安全確保支援士の科目Bの「〇〇字以内で答えよ」「空欄に入れる字句を答えよ」のような形式。タップではなく、利用者が短く入力する。

### 出し方
- 問題文に答え方の条件を書く: 「字句で答えよ」「数値で答えよ（単位は不要）」「40字以内で答えよ」
- 空欄補充なら空欄を【 a 】のように示し、複数の空欄があれば「a: 〜、b: 〜 の形で」と答え方を示す
- 入力は Other 欄ではなく通常のメッセージで受け取る（AskUserQuestion は使わない）

### 出題前に作っておくもの（進行表に書く）
- 模範解答
- **採点基準**: 必ず含むべき要素（キーワード・条件）と、別解として認める表現・表記ゆれ（例: 「IPsec」「IPSec」、「SYNフラッド」「SYN Flood」）
- 字数制限があれば、模範解答がその字数に収まっていること

### 採点
- 語句・数値: 採点基準と照合する。表記ゆれ・同義語は正解。単位の付け忘れは本番の扱いに合わせる
- 字数制限の記述: 要素ごとに ○/△/× を付け、「正解 / 部分正解 / 不正解」で判定する。字数超過は本番では0点になりうるので、超えていたら必ず指摘する
- 判定の根拠を示す（「『送信元の偽装』が書けているので○、『応答が攻撃先に届く』が抜けているので△」）
- 公式の採点基準は非公開の試験が多いので、「自己採点の目安」と書き添える
- 誤答分類は択一と同じ3種に、「答え方のずれ（字数・問われた形式で答えていない）」を加える

## 6. 図表が要る問題

ネットワーク構成図、E-R図、シーケンス図、表、グラフ、擬似言語のプログラムなど。図がないと問題として成り立たないものは、図を省いて文章だけにしない（本番の難しさの多くは図を読むところにあるため）。

### 図の出し方（使える中で上のものを選ぶ）
1. **表**: Markdown の表。ログ、設定値、ルール表、比較表に向く
2. **テキスト図**: コードブロック内の罫線・矢印の図。スマホでも崩れにくいよう横幅は40字程度に抑える
   ```
   [PC]──[L2SW]──[FW]──[ルータ]──(インターネット)
                   │
                 [DMZ]──[Webサーバ]
   ```
3. **Mermaid**: 表示できる環境ならシーケンス図・フローチャート・E-R図に使う
4. **画像・SVG・HTML**: 図を描画して見せられるツール（インライン表示のウィジェット、画像として送れるツールなど）があればそれを使う。描いた図は自分で一度見て、線のつながりやラベルが読めるかを確かめる

### ルール
- 図は問題文の直前のメッセージに出し、AskUserQuestion の `question` には「上の図を見て答えてください」と問題文を入れる
- 図に正解のヒントを入れない（強調表示や、答えに当たる部分だけ詳しく描くなど）
- 図の中の名前（機器名・テーブル名）は問題文・選択肢と一致させる
- 出題前の点検に「図だけを見て、問題文の条件どおりの構成になっているか」を足す
- 解説でも図を使い、どこを見れば判断できたかを示す

## 7. 大問・小問の構成

長文のシナリオに設問が複数ぶら下がる試験（支援士の科目Bなど）。

- シナリオ（と図）を最初に1回出し、設問は1問ずつ出す。見出しは「問2 設問1(2)」のように本番の番号に合わせる
- 各設問の後に解説するか、大問の最後にまとめて解説するかは、学習モードでは設問ごと、模試・お試しテストでは最後にまとめる
- シナリオが長いと設問のたびに読み返せないので、設問の中で必要な箇所を「（本文〔3〕より）」のように指せるよう、シナリオに段落番号を付ける
- 1つの大問は複数の小項目にまたがるので、割り当て（`coverage.md`）では設問ごとに小項目を数える
