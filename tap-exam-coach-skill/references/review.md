# 誤答分類・弱点ノート・想起テスト・再出題

## 1. 誤答分類（3種。試験に合わせて言い換える）

| 分類 | 意味 | CISSPでの言い方 |
|---|---|---|
| 知識不足 | 用語・暗記・区別が分かっていない | 知識不足 |
| 読み違い | 問題文の条件（「最初に」「最も」「〜でないもの」）を読み落とした | 読み違い |
| 試験の視点とずれた | 知識はあるが、試験が求める立場と違う立場で選んだ | 技術者視点で選んだ（CISSPはマネージャー視点を求める） |

短答では4つ目に「答え方のずれ（字数超過、問われた形式で答えていない）」を加える。

3つ目は試験ごとに言い換える。例:
- 情報処理安全確保支援士: 「現場の運用担当視点で選んだ」
- クラウド認定: 「コスト・運用負荷より技術的に凝った案を選んだ」

利用者の経験（`exam-profile.md`）から、ずれやすい方向を初期設定で決めておく。

細目として「似た用語の区別」「暗記（順序・数値・法律名）」を付けると傾向が見えやすい。CISSPでは誤答の大半が「似た用語の区別」だった（オーナー/カストディアン、RPO/RTO、ECB/CTR、DH/RSA、衝突耐性/第二原像など）。

分類は解説を出したあとにスキル側で付ける。迷うときは利用者に「どれを選んだ理由は？」と軽く聞いてよい（任意。毎回は聞かない）。

## 2. 弱点ノート

誤答のたびに `weak-notes-wN.md` に書く。

```
- 問9 暗号利用モード: 同じ平文ブロック→同じ暗号文をC CTRと回答、正解はB ECB。
  ECB=ブロックを独立に暗号化、パターンが残る。CTR=カウンタを暗号化して鍵ストリーム化…
  分類: 知識不足（用語の区別）
```

- 論点、自分の回答と正解、区別のポイント（**正解と誤答した選択肢の両方の定義**）、分類
- 週ごとにファイルを分ける（1ファイルが大きくなると読み込めなくなったため）

### 週末の「結果」

週の本編と想起テストが終わったら、同じファイルの末尾に書き、利用者にも示す。

- 本編の正答数と正答率、想起テストの回復数
- 小項目別の正答
- 正解位置の分布（実際に出した A/B/C/D の数）
- Aへの誤答の数（おすすめ印を使った環境では特に）。回答時間が分かれば、30秒以内の速い誤答の位置
- 誤答の傾向（分類・細目の内訳、繰り返している論点）
- `coverage.md` との照合結果（抜けた小項目とその回し先）

## 3. 想起テスト

- 週の本編の後に、前週までの誤答論点から数問出す（2〜10問。未回復の論点を優先）
- 回答形式は元の問題と同じ形式（択一・短答など）。**問題文は元の問題と変える**（同じ問題の丸暗記を防ぐ）。問い方を変える、逆から問う（定義→用語、用語→定義）、シナリオに入れるなど
- 見出しは「想起1/5」のように本編と分ける。解説は学習モードと同じ型
- 結果を論点ごとに「回復 / 未回復」で記録する

## 4. 再出題のルール

- 未回復の論点は、弱点補強週に必ず再出題する
- **同じ誤答を2回した論点**（CISSPでは SSD に消磁、CFAA と FISMA、Biba の規則名）は、単発の問題ではなく**一覧形式で整理してから**出す。例:
  - 米国法の名前と対象の一覧表
  - BLP と Biba の規則名の対比表
  - 媒体別のサニタイズ方法（消磁が効く/効かない）の表

  一覧を見せたあと、その一覧から2〜3問出して確かめる。想起テストで回復しない論点は、単発の再出題より一覧での整理が効いた実績がある
- 正答率が特に低い小項目（CISSPでは 3.6 暗号が 5/10）は、弱点補強週に5問ほど追加する

## 5. 弱点補強週の組み方

1. 全週の弱点ノートから、未回復の論点・2回誤答した論点・正答率の低い小項目を集める
2. 模試の分野別正答率が低い分野を加える
3. `coverage.md` の「抜け」を加える
4. これらで割り当てを作り（一覧整理が要る論点は先に一覧）、通常の週と同じように示してから出題する
