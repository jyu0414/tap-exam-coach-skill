# 記録ファイル

## 置き場所

会話が切れても次のセッションで続けられる場所に置く。

- Claude Code: 作業ディレクトリの `exam-coach-data/<試験の短い名前>/`（例: `exam-coach-data/cissp/`）。利用者が別の場所を指定したらそこ
- Claude.ai のプロジェクト: 正本はプロジェクトの知識。Claude は知識を書き換えられないので、スレッドの終わりに更新版を渡して利用者に入れ替えてもらう。ファイルの絞り方（弱点ノートを1つにまとめる等）と手順は `project-threads.md`
- 永続化できる場所がない環境: 初回に「この環境では記録が会話をまたいで残りません」と伝え、週末ごとに `progress.md` 相当の要約をメッセージで渡して、次回貼ってもらう

置き場所を決めたら `progress.md` の先頭に書いておく。

## ファイル一覧

| ファイル | 中身 | 雛形 |
|---|---|---|
| `progress.md`（索引） | 今どの週のどこか、各週の結果の1行要約、次にやること | `templates/progress.md` |
| `exam-profile.md` | 試験情報、利用者の設定 | `templates/exam-profile.md` |
| `plan.md` | 週割、判断点の基準、TODO、計画の変更履歴 | `templates/plan.md` |
| `coverage.md` | 小項目一覧、週ごとの割り当て、照合結果、抜け | `templates/coverage.md` |
| `question-rules.md` | 出題ルール。利用者の指摘で変わったら追記 | `references/question-rules.md` 4章の要約から作る |
| `weak-notes-wN.md` | 週ごとの進行表、誤答、結果 | `templates/weak-notes.md` |
| `mock-results.md` | 模試ごとの総合・分野別の正答率、所要時間、判断 | `templates/mock-results.md` |
| `mock-N-answers.md` | 模試Nの正解表と回答表（作業用） | なし（進行表と同じ1問1行） |
| `quick-check-YYYYMMDD.md` | お試しテストの正解表と回答表（作業用）。結果は `mock-results.md` に「お試し」として追記 | なし |

## 進行表（1問1行、出題しながら更新）

`weak-notes-wN.md` の「進行表」に書く。

```
- 問14: 3.6 / 事前共有なしで共通鍵を合意=DH（RSAの鍵輸送との区別）/ 正解C / A誤答（39秒）
```

項目: 問番号、小項目、論点、正解（短答は模範解答と採点基準）、利用者の回答と正誤、回答時間（分かれば）。

**出題前に**「問14: 3.6 / 論点 / 正解C /」まで書き、回答後に正誤を足す。先に正解を書くことで正解位置の分布を管理でき、会話が切れても採点できる。

## progress.md の更新タイミング

- 初期設定の終わり
- 10問ごと程度（「W5 問12/25まで」）
- 週末（その週の1行要約と次にやること）
- 模試の開始・中断・終了
- 計画の変更

## セッション開始時の動き

1. `progress.md` を読み、今の週と次にやることを確かめる
2. 週の最初なら、`coverage.md` の割り当てを示す
3. 途中なら、進行表の最後を見て次の問題番号から再開する（正解を書いたが回答がない問題があれば、その問題から出し直す）
4. 利用者に「W5 問13から再開します」のように一言伝えてから出題する
