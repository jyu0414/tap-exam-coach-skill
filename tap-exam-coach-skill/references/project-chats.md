# Claude.ai のプロジェクトで進める

Claude.ai のプロジェクトには2種類ある。どちらかを最初に見分ける。

| 見分け方 | 種類 | 記録の置き場所 |
|---|---|---|
| `/mnt/project-files/` があり、`post_widget` や `request_decision` が使える。画面にメイン（コーディネーター）とスレッドがある | **新しいプロジェクト** | `/mnt/project-files/exam-coach-data/<試験の短い名前>/`。ライブラリに自動で残るので、ファイルの受け渡しは要らない |
| 上がなく、プロジェクトの知識（ナレッジ）が読み込まれている | **従来のプロジェクト** | 知識のファイル。下の「従来のプロジェクト」の手順で受け渡す |

## 新しいプロジェクト（メイン画面＋スレッド）

2026-11-14 に実機で確かめた動き:

- 利用者が「〇〇を学習したい」と送ると、メイン画面（コーディネーター）はスレッドを作って任せることが多い。スキルはそのスレッドで読み込まれる
- メインでもスレッドでも、`post_widget` のカードでタップの出題ができ、`/mnt/project-files/` の記録を読み書きできる（出し方は `question-rules.md` 2章）
- 記録は1問ごとに `/mnt/project-files/exam-coach-data/<試験>/` に書く。会話が切れても、次にメインやスレッドで「続き」と言われたら、そこの `progress.md` から再開する
- 知識ファイルの入れ替えや「チャットの終わりにファイルを渡す」手順は不要。利用者に頼まない

メイン画面として動いているとき:

- 試験対策の依頼は、スレッドを1つ作って任せてよい。そのとき指示に「出題は `post_widget` のカード（ボタンはA〜D、`card_as_is: true`、おすすめ印・`primary` なし）で出す」「記録は `/mnt/project-files/exam-coach-data/<試験>/`」と書く
- 週ごとに新しいスレッドを作るか、1つのスレッドで続けるかは利用者に聞く（既定は1つのスレッドで続ける）
- 利用者がメインで「問題を出して」と言ったら、スレッドに回さずメインで出してもよい。どちらで出しても記録は同じファイルに書く

スレッドとして動いているとき:

- 出題は自分で `post_widget` のカードで行う。決定カード（`request_decision`）で出題をメインに回すのは、`post_widget` が表示されないと利用者が言ったときだけ
- 利用者から「カードが出ない」と言われたら、どの画面（メインかスレッドか、スマホかWebか）で見ているかを聞き、`question-rules.md` 2章の順で出し直す

## 従来のプロジェクトで、週ごとにチャットを分けて進める

Claude.ai では試験ごとに1つのプロジェクトを作り、週・模試・お試しテストごとに新しいチャット（チャット）を立てて進める。1チャットが長くなりすぎず、あとから「W5のチャット」を開けば、その週の問題と解説を見返せる。

### 前提（2026年11月時点の公式ヘルプで確認したこと）

- プロジェクトの知識（ナレッジ）にファイルを入れられるのは利用者だけ。Claude はチャットの中から知識のファイルを追加・書き換えできない。だから**記録の更新は「Claude が更新版のファイルを渡す → 利用者が知識のファイルを入れ替える」**で行う
- プロジェクトの知識は、そのプロジェクトのどのチャットからも読める
- 有料プランでは、同じプロジェクト内の過去チャットの検索やプロジェクトごとのメモリーが使えることがある。ただし設定で切られていることもあるので、**記録の正本は知識のファイルにする**。過去チャットの検索は、知識のファイルに書いていないことを確かめる補助にだけ使う
- 知識のファイルが作業用のどのパスに置かれるかは公式に書かれていない。決まったパスを前提にせず、会話に読み込まれている知識の中身を読む

制度や画面は変わる。うまくいかないときは、この節を前提にせず、利用者に画面の様子を聞いて合わせる。

### チャットの単位

| チャット | 名前の例 | やること |
|---|---|---|
| 初期設定（W0） | `W0 初期設定` | 試験の調査、計画、割り当て。最後に知識へ入れるファイル一式を渡す |
| 週 | `W5 第3分野` | その週の割り当てを出題し、週末の振り返りと想起テストまで。最後に更新版を渡す |
| 模試 | `模試2` | 模試を1本。採点と判断まで |
| お試しテスト | `お試し 11/14` | 20問ほど。結果を渡す |

利用者が「1日1チャット」など別の単位を望んだら、それに合わせる。単位を変えても、終わり方（下の「チャットの終わり方」）は同じ。

### 知識に置くファイル

知識のファイルは数を絞る。毎週入れ替えるのは `progress.md` と `weak-notes.md` が中心になる。

| ファイル | 中身 | 入れ替える時 |
|---|---|---|
| `progress.md` | 今どの週か、各チャットの1行要約、次のチャットでやること | 毎チャットの終わり |
| `exam-profile.md` | 試験情報（出典つき）、利用者の設定 | 初期設定、試験の情報が変わったとき |
| `plan.md` | 週割、判断点、TODO、変更履歴 | 計画を変えたとき |
| `coverage.md` | 小項目一覧、週ごとの割り当てと実績 | 毎週の終わり |
| `weak-notes.md` | **全週ぶんの弱点ノートを1つにまとめたもの**。未回復の論点が上、回復した論点は下に1行で残す | 毎チャットの終わり |
| `mock-results.md` | 模試・お試しテストの結果 | 模試・お試しのチャットの終わり |

1問1行の進行表（`weak-notes-wN.md` の中身）は、そのチャットの中にあれば足りるので知識には入れない。週の終わりに、誤答だけを `weak-notes.md` に移す。

### チャットの始め方

1. 知識の `progress.md` を読み、今の週と「次のチャットでやること」を確かめる
2. 知識のファイルが見当たらない、または古そうなら（`progress.md` の最終更新が前のチャットより前など）、「前のチャットの最後に渡したファイルを知識に入れ替えましたか？」と聞く。入れ替えていなければ、前のチャットを開いて最後のメッセージのファイルを入れてもらう
3. 週のチャットなら、`coverage.md` の今週の割り当てを示してから出題する。前週の想起テストが残っていれば先にやる
4. チャットの名前を提案する（例: 「このチャットの名前は `W5 第3分野` にしておくと後で探しやすいです」）

### チャットの中

- 進行表はそのチャットの中で持つ。ファイルを作れる環境なら作業用の `weak-notes-wN.md` を作り、1問ごとに更新する。作れない環境なら、出題前の正解表を会話に出さずに自分の中で管理するのは難しいので、ファイル作成（コード実行）を有効にしてもらう
- 同じ週のうちに中断したら、同じチャットに戻って「続き」と言ってもらう。新しいチャットを立てる必要はない
- 週の途中で別の週のチャットを立てられたら、`progress.md` と照らして「W5がまだ途中です。W5のチャットで続けますか？」と確かめる

### チャットの終わり方

週の割り当てと振り返りが終わったとき、または利用者が「今日はここまで」「次の週へ」と言ったときに行う。

1. その週の結果を短くまとめる（正答率、分野ごとの傾向、未回復の弱点の数）
2. 更新したファイルを**ダウンロードできるファイルとして**渡す。中身が変わったものだけ渡し、変わらないものは「変更なし」と書く
3. 入れ替え方をそのまま書く。例:

   > プロジェクトの知識で、次の2つを古いものと入れ替えてください（古いファイルは削除してから追加）。
   > - `progress.md`
   > - `weak-notes.md`
   > `coverage.md` と `plan.md` は変更なしです。

4. 次のチャットの始め方を書く。例: 「入れ替えたら新しいチャットで『W6を始めて』と送ってください。おすすめの名前は `W6 第4分野` です」

週の途中で止める場合は、`progress.md` に「W5 問12/25まで」と書いて渡すが、続きは同じチャットでやるよう伝える。

### 初期設定のチャット（W0）で最初に渡すもの

1. 知識に入れるファイル一式: `progress.md`、`exam-profile.md`、`plan.md`、`coverage.md`、`weak-notes.md`（空の雛形）、`mock-results.md`（空の雛形）
2. プロジェクトの指示に貼る文（`templates/project-instructions.md` を試験名で埋めたもの）
3. 「プロジェクトの知識に6つのファイルを入れ、指示に上の文を貼ってから、新しいチャットで『W1を始めて』と送ってください」という一言

まだプロジェクトの中にいない（ふつうのチャットで始めた）なら、先にプロジェクトを作るよう勧める。作るかどうかは利用者が決める。
