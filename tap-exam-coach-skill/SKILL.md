# tap-exam-coach-skill: 資格試験の出題・学習管理

利用者が「受けたい試験」と「受験日」を伝えたら、試験の出題範囲と出題形式を調べて計画を作り、本番と同じ形式で1問ずつ出して解説し、弱点を記録して定着させる。利用者は「自分で説明を書く」より「選ぶだけで学べる」形式を好み、スマホでも使う。だから択一はタップで受け取り、短答だけは短く入力してもらう。

## まず記録を確かめる

会話は途中で切れる。続きから始められるように、学習の状態はすべてファイルに残す（書式は `references/records.md`）。

1. 保存先フォルダ（既定: 作業ディレクトリの `exam-coach-data/<試験の短い名前>/`）に `progress.md` があるか見る
2. あれば読み、今の週・次にやることを確かめて、そこから再開する。週の最初なら小項目の割り当てを示してから出題する。途中なら次の問題番号から続ける
3. なければ初期設定に進む（お試しテストを頼まれたときは初期設定なしで始めてよい）

## モードの切り替え

| 利用者の言葉 | やること | 読むファイル |
|---|---|---|
| 「〇〇に合格したい」「計画を立てて」（記録なし） | 初期設定: 試験情報・出題形式の調査、計画、割り当て | `references/setup.md` |
| 「問題を出して」「続き」 | 学習モード | `references/question-rules.md` ＋ `references/formats.md` |
| 「今受けたら受かりそう？」「お試し」「サクッと実力を見たい」 | お試しテスト（いつでも、20問ほど） | `references/quick-check.md` |
| 「模試をやりたい」、計画上の模試週 | 模試モード | `references/mock-mode.md` |
| 週末、誤答の整理、想起テスト、弱点補強週 | 振り返り | `references/review.md` |

出題する前には必ず `references/question-rules.md` と `references/formats.md` を読む。問題の質・回答UI・形式ごとの出し方はそこにまとまっている。

## 毎回守るルール（理由つき）

運用で実際に起きた失敗から決めたルール。詳細と例は question-rules.md と formats.md。

1. **本番と同じ形式で出す。** 選択肢の記号（A〜D、ア〜エ…）・数・複数選択・短答・図表の有無は、調べた本番の形式に合わせる。形式がずれると本番の感覚に近づかない。
2. **択一はタップで選ばせる。** Claude Code なら AskUserQuestion（label に記号、description に本文）。選択肢が5つ以上ある・タップUIがない環境ではテキスト入力。短答は通常のメッセージで入力してもらう。
3. **回答前に正解やヒントを一切出さない。** 正解を先に見ると学習にならないと利用者が明言している。選択肢に理由を書き添える（「〜のため」）のもヒントになるので避ける。
4. **見出しは番号だけ（「問3/25」）。** 小項目名・分野名はヒントになるので出さない。週の中でも小項目の順番はシャッフルする。
5. **正解位置を均等に散らし、先頭の選択肢が正解の問題も必ず混ぜる。** 出題前に進行表へ正解を書き、分布を管理する。
6. **「おすすめ」印は付けない。** UIが印を必須にする場合だけ常に先頭に固定し、毎回「おすすめ表示は正解と関係ありません」と書き添える。印の位置へ誤答が寄った実績がある。
7. **網羅を先に決める。** 週の最初に小項目ごとの問題数を示し、全小項目に最低1問を割り当ててから出題する。
8. **本番より簡単にしない。** 選択肢は同じ形・長さ・具体性の実在する用語や施策にし、図が要る問題は図を省かない。正解が1つに決まることを出題前に自分で点検する。
9. **1問ごとに記録を更新する。** 進行表と弱点ノートに書いてから次の問題へ進む。
10. **試験の事実は記憶で言わない。** 出題比率・形式・科目名・合格基準は、`exam-profile.md` に出典つきで書かれたものか、その場で実施団体の公式資料（試験要綱・試験ガイド・公式サンプル問題）を開いて確かめたものだけを使う。お試しテストや「1問だけ出して」でも同じ。資格試験は制度変更が多く（例: 支援士は2026年度からCBT化し、科目A・科目Bの呼び方になった）、記憶は古いことがある。特に**利用者の言葉遣いを記憶だけで訂正しない**。

## 解説の型（学習モード）

回答を受け取ったら次の順で出す。

1. 正誤と正解（短答なら判定の根拠も）
2. 正解の理由
3. 他の選択肢がなぜ劣るか（各1〜2文）
4. 試験が求める判断軸（例: CISSPは「マネージャー視点」）
5. 似た用語の区別や覚え方。誤答した選択肢と正解の両方の定義を並べる（誤答の大半は似た用語の混同だった）
6. 教材間で定義が揺れる論点は「教科書で要確認」と書く

## 計画を勝手に変えない

模試の結果が判断点の基準を下回っても、受験日の後ろ倒しは**案を示して利用者に決めてもらう**。お試しテストの結果では計画を動かさない。計画の変更は `plan.md` の変更履歴に残す。

## ファイル一覧

- `references/setup.md` — 入力の聞き方、試験情報と出題形式の調査、週割、判断点、TODO、小項目の割り当て
- `references/question-rules.md` — 1問の流れ、回答UI、おすすめ印、問題文のルール、出題前の点検
- `references/formats.md` — 形式別の出し方（N択、複数選択、組合せ、短答、図表、大問）
- `references/quick-check.md` — お試しテスト
- `references/mock-mode.md` — 模試の構成、進め方、採点
- `references/review.md` — 誤答分類、弱点ノート、想起テスト、再出題
- `references/records.md` — 記録ファイルの書式と置き場所
- `templates/` — 記録ファイルの雛形。初期設定でコピーして埋める
